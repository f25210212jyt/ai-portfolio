## README 里「已知问题」为什么要诚实写？

在工程开发中，诚实地记录“已知问题”不仅是专业素养的体现，更是对使用者负责。首先，它可以**降低沟通成本和排错成本**。没有任何软件是完美的，如果不写明（比如“未启动Ollama时本地模式会报错”），使用者遇到报错时会认为是代码存在严重缺陷，从而浪费大量时间去翻找源码。写明它，等于给了使用者一份排障指南。其次，**藏着掖着是埋雷**。掩饰已知问题会破坏项目的可信度，让人觉得作者缺乏严谨性。暴露问题不仅体现了我们对产品边界的清晰认知，也能吸引其他开发者一起改进。最后，“已知问题”也是开发者自身成长的记录。承认限制，意味着我们清楚当前的架构瓶颈在哪里，这是迈向更优版本（v2.0）的起点。
